# **Realimentación Estudiantil con Inteligencia Artificial**

Esta es una herramienta que busca facilitar la construcción de reportes de realimentación personalizada para cada estudiante. Manteniendo la privacidad de los datos del estudiante y con la facilidad de construir y modificar el reporte con las herramientas de IA, en base a los comentarios que ingrese el docente día a día. 

La herramienta posee las siguientes pestañas:
1. **Estudiantes**: En esta pestaña se pueden gestionar los estudiantes y su partenencia a una o varias clases. Todo esto dentro del marco de educación básica, primaria y media en Colombia. Este es el único espacio donde se guardan los nombres de los estudiantes y se asocian a su identificación personal. Esto se hace en una base de datos SQL y la IA solo tiene acceso a un identificador único del estudiante, por tanto no tiene información sensible de los estudiantes. Al momento de desarrollar los informes, escribe el documento y de forma local se cambian las menciones de variables del estudiante por las variables adecuadas, por ejemplo: [NOMBRE_ESTUDIANTE], [ID_ESTUDIANTE], etc.
2. **Cursos y clases**: En esta pestaña se pueden gestionar los cursos y las clases. Las clases son las materias específicas (por ejemplo: Matemáticas, Ciencias Sociales, etc.) y los cursos son los grados y secciones (por ejemplo: Noveno B, Décimo, Cuarto A, etc.). Aquí también se puede ver y cambiar los estudiantes de cada clase o curso. 
3. **Rúbricas**: En esta pestaña se pueden configurar las rúbricas que se utilizan para calificar los reportes. Estas rúbricas deben seguir una estructura de dimensión y una escala de valoración discreta/continua. Con etiquetas para cada tramo y una calificación numérica de 0 a 5 para cada dimensión. Se debe poder poner nombre a cada tipo de rúbrica. 

4. **Reportes**: En esta pestaña se pueden construir los reportes de realimentación. Estos reportes poseen una estructura básica de Estudiante, clase, curso, fecha, contenido (texto, con STT *Speech-to-text*) y calificación según rúbrica (Un reporte puede tener anexo una rúbrica, solo una). La idea es que también el profesor pueda automatizar este proceso seleccionando una clase (química, ciencias sociales, idiomas, etc.) o un curso (noveno B, Décimo, Cuarto A, etc.) y solo tenga que hablar y presionar el botón de siguiente. La idea es que a partir de la rúbrica el profesor solo diga que puntuación le da en cada categoría o la IA lo interprete del comentario. Los reportes, individuales o colectivos quedan guardados como JSON en una base de datos SQL de PostGres en Railway. 

4. **Informes**: En esta pestaña se construyen los informes, estos se realizan escogiendo uno o varios estudiantes o uno o varios cursos/clases junto a una fecha de inicio y final. La herramienta toma los JSON de los reportes que cumplen con los filtros y puede generar un documento Word o PDF con los informes que pueden ser de cada estudiante de el conjunto de cursos o clases seleccionados o del curso o clase completo. También, cada informe debe tener un espacio para asignación de un prompt con detalles.

Se debe poder guardar un modelo de informe, para poderlo ejecutar posteriormente. 

Para cada informe, se debe mostrar la evolución de la calificación de cada una de las dimensiones de la rúbrica de los reportes que la componen. Por ejemplo, si tenemos un informe del último semestre para una clase de Matemática en Septimo grado, por estudiantes y en los reportes solo se toman los que usan la rúbrica de "Habilidades de matemática" con dimensiones como "Habilida de razonamiento", "Pensamiento estructurado" y "Pensamiento lógico", se debe mostrar la evolución de la calificación de cada una de estas dimensiones a lo largo del tiempo para cada estudiante tomando la valoración de cada reporte como una observación. Si se hace lo mismo para el curso o clase entero, se saca el promedio con la valoración de todos los estudiantes, para cada dimensión, la media, mediana y cuartiles. 

Las gráficas deben funcionar de la siguiente manera. Todas son gráficas de líneas, cada una debe tener los ejes X y Y bien identificados. La gráfica X debe mostrar el tiempo (por ejemplo, meses o semanas), y la gráfica Y debe mostrar la calificación según la escala de la rúbrica. La idea es poder ver la evolución de la calificación de cada una de las dimensiones de la rúbrica, donde cada línea sea una dimensión y cada gráfica represente los resultados de una rúbrica. 

Para los reportes agregados, sería similar, solo que, en este caso, cada línea representa el promedio de los estudiantes que tienen reportes con esa rúbrica en ese periodo y cada punto de la línea tiene cajas y bigotes para cuartiles y una línea punteada para la media. 

## **Tecnología**
La tecnología usada para su despliegue es railway, Python con FastAPI, HTMX y PostGres nativo de railway. Esta herramienta está desarrollada por el GovLab de la Universidad de la Sabana y debe seguir un manual de marca usando el Logo del GovLab, Publico Banner Light Italic para títulos y Franklin Gothic para el resto del contenido, siguiendo en documento CSS compartido.
